# 团队工作流程规范

## 角色职责

| 角色 | 职责 | 限制 |
|------|------|------|
| **architect** | 架构设计、功能分析、任务拆分、任务分发、审核测试用例 | ❌ 不能写代码 |
| **developer** | 功能开发、代码实现、bug修复 | ✅ 只能开发分配的任务 |
| **tester** | 测试用例设计、测试执行、验证功能 | ✅ 同步编写测试代码 |

## 标准工作流程

```
┌─────────────────────────────────────────────────────────────────┐
│  Phase 1: 架构师分析                                              │
│  architect: 功能比对分析 → 识别未实现功能 → 创建任务并拆分           │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 2: 测试先行                                                │
│  tester: 根据任务设计测试用例                                       │
│  architect: 审核测试用例 → 通过后进入下一阶段                         │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 3: 开发与测试并行                                           │
│  developer: 实现功能代码                                           │
│  tester: 同步编写测试代码                                          │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 4: 验证完成                                                │
│  tester: 执行测试 → 验证功能                                       │
│  通过 → 标记任务完成，进入下一任务                                   │
│  不通过 → developer 修复 → tester 重新测试                          │
└─────────────────────────────────────────────────────────────────┘
                              ↓
                         重复迭代...
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 5: 全部完成                                                │
│  architect: 确认所有任务完成 → 通知用户                              │
└─────────────────────────────────────────────────────────────────┘
```

## 关键规则

1. **测试先行**: 测试用例必须先设计，架构师审核通过后才能开始开发
2. **单任务串行**: developer 一次只处理一个模块，测试通过后才能继续下一个
3. **架构师不写代码**: architect 只负责设计、分析、审核、分发，不能参与实际编码
4. **测试必须通过**: 每个模块必须经过 tester 验证通过才能标记完成
5. **持续迭代**: 任务完成后自动进入下一个任务，直到全部完成

## 任务状态流转

```
pending → in_progress(developer) → testing → completed
                ↑                      ↓
                └────── fix ───────────┘
```

## 通信规范

- 任务完成或遇到阻塞时，通知 architect
- architect 负责协调整个团队的工作节奏
- 所有成员通过 SendMessage 沟通，不要独立行动
